# 版本说明：课程讲的 1.20 与仓库跑的 1.18.1

这一页解释一个容易被误解的地方：**课程里的概念没有错，仓库里也没有偷偷改代码**，只是两者依据的 Slint 版本不同。

## 事实

| | 课程视频 | 本仓库 |
| --- | --- | --- |
| 依据 | Slint 官方文档 latest（以 `edition 1.20` 为例） | 本机 crates.io 可获得的最高版本 `slint 1.18.1` |
| 用途 | 讲清语言设计与语法语义 | 提供能真的编译、能真的跑的配套代码 |
| 声明方式 | 文档示例里写 `#[edition = "1.20"]` | `Cargo.toml` 锁 `slint = "=1.18.1"` |

本机 `cargo info slint` 返回 1.18.1，`cargo info slint@1.20.0` 报「registry 中找不到该版本」。也就是说制作时无法用 1.20 实测，因此仓库选择与**可验证环境一致**的版本，而不是写一个没跑过的工程。

## 具体改了什么

1. 官方教程的 Rust 单文件示例用 `slint::slint! { ... }` 宏，宏体第一行是 `#[edition = "1.20"]`。1.18.1 的解析器不认识该属性，会直接报 `Parse error: expected a top-level item such as a component, a struct, or a global`。还原工程时**只移除这一行**，其余代码逐字未改。
2. 为了贴合课程 P02 讲的真实项目结构，把宏体拆成独立的 `ui/app-window.slint`，配 `build.rs` + `slint::include_modules!()`。这是结构整理，不是语法改写。
3. 删除官方文档里的 `// ANCHOR:` / `// ANCHOR_END:` 片段锚点注释（它们不是代码）。

## 哪些差异会真的看得见

- **绑定环诊断**：课程 P04 / P14 讲「子元素撑起父元素」造成的绑定环，依据是「**1.19 起 `if` 里的 Text 也参与父元素尺寸计算**」。1.18.1 仍按旧行为，因此 `compile-fail/p04_s17.slint`、`p14_s11.slint` 在本机不会报课程里那条错误。
- **赋值覆盖绑定警告**：课程 P01 讲的 `assignment will overwrite the binding`，1.18.1 未输出该警告。

这三条反例的**课程标注**、**本机实测输出**与差异原因都在 [`compile-fail/README.md`](../compile-fail/README.md) 里逐条列出，没有为了凑报错而改写官方片段。

## 如果你用的是 1.20 或更新版本

1. 把 6 个工程的 `Cargo.toml` 里 `slint` / `slint-build` 的 `=1.18.1` 改成你的版本；
2. 在 `ui/app-window.slint` 顶部加回 `#[edition = "1.20"]`（或按官方文档用项目文件 / `CompilerConfiguration::with_edition` 声明）；
3. 语法主体不受影响，课程 P08 专门讲了 edition 的作用与声明位置。

## 图标

官方教程引用 `icons/at.png` 等 8 张图标，本仓库没有分发官方素材，而是用纯标准库生成了 8 张不同底色 + 编号的**占位 PNG**（`icons/` 及每个工程的 `ui/icons/`）。文件名与官方一致以便对照，游戏配对逻辑照常工作；想换成官方图标，直接覆盖对应 PNG 即可。
