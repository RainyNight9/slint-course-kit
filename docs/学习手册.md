## P01 · 为什么是 Slint

**Why Slint** · 视频 10.44 分钟 · `ep01.mp4`

### 本集目标

1. **说清 Slint 解决什么问题** —— 能用自己的话讲出命令式写 UI 的痛点和声明式的解法
2. **理解响应式绑定的含义** —— 知道「属性变了界面自动更新」背后是细粒度依赖追踪
3. **算明白三重许可的账** —— 知道自己的项目该走 GPLv3、Royalty-free 还是商业许可

### 核心规则

- **依赖登记** —— 绑定求值时访问的属性，自动成为它的依赖
- **脏标记** —— 属性变了，只有依赖它的绑定被标脏
- **惰性求值** —— 值被读取时才真正重算，没人读就不算
- **GPLv3** —— 开源项目免费商用，你的代码可以保持自己的许可
- **Royalty-free** —— 闭源桌面/移动/Web 应用免费，需展示 Slint 署名（如 AboutSlint）
- **商业许可** —— 嵌入式设备与无署名展示的闭源场景，按席位付费

### 关键结论

- **同一份 .slint，四类目标**：MCU 微控制器、嵌入式 Linux、桌面 / 移动、WebAssembly
- **Slint：你能表达的只有 UI**：网络请求？回宿主语言、数据处理？回宿主语言
- **微控制器上的 Slint：几百 KB 就能跑**：ESP32、STM32、Raspberry Pi Pico

### 容易踩的坑

- 这个排序——嵌入式排在最前面。
- 踩的天条：绑定只在属性「持有它」期间有效。
- 文档和示例另算——它们是 MIT，随便用。

### 随堂练习

**题目**：JSX 同样是声明式，也能把逻辑混进界面文件；Slint 刻意不提供这种能力，这算缺点还是设计？

提示：想想「边界由谁来保证」——是团队的自觉，还是语言本身？

**答案讲解**：是设计，而且是核心设计。Slint 是纯声明式语言，语言层面就装不下网络请求和数据处理，业务逻辑必须回到宿主语言。这换来了三条收益：UI 代码永远可读、设计师可以直接参与改界面、两边的边界由编译器而不是团队纪律来保证。官方文档把这一点称为「真正的声明式语言」。

### 知识地图

1. **纯声明式语言**（P08）—— 从零设计而非改造宿主语言，是后面所有语法的出发点
2. **细粒度响应式**（P08）—— 绑定自动重算是 Slint 动态行为的根基
3. **UI 与逻辑分离**（P16）—— 属性与回调是两个世界的唯一通道

## P02 · 搭好环境，跑起第一个程序

**Getting Started** · 视频 9.22 分钟 · `ep02.mp4`

### 本集目标

1. **两条起步路都走一遍** —— 模板能一键跑起来，手搭的三件套也说得出各自职责
2. **看懂编译期发生了什么** —— build.rs 编出什么、组件名怎么变成 Rust 结构体
3. **把实时预览用起来** —— 会开、会用，也知道它什么时候必须让位给重启

### 核心规则

- **编译前执行** —— 先运行 build.rs，再编译你的 crate
- **输入变了才重跑** —— 依赖或 .slint 改动时重新执行一次
- **失败即中断** —— 脚本里 panic 或返回错误，整个构建停下
- **顶层** —— 对应一个真实窗口，由系统管理
- **不可嵌套** —— Window 里放不了 Window，只能当组件根
- **尺寸** —— 没写宽高时按内容推算初始大小
- **属性 / 布局 / 动画** —— 保存即生效，程序不重启
- **改名 / 删属性 / 改签名** —— 宿主失联，需重编译

### 关键结论

- **预览时界面由解释器加载**：属性、回调、模型都保留、语法错误时旧界面不动
- **环境就绪**：下一站：MemoryTile、P03

### 容易踩的坑

- 急着改代码，花两分钟看清目录：Cargo.toml 声明依赖，build.rs 管编译期的界面处理，ui 放 .slin。
- 错的一步，是把 slint-build 加成了普通依赖。
- 急着 unwrap。
- 对齐要有余量才看得见，默认 Text 刚好包住文字，这时设居中没效果。
- 小看扩展的诊断能力。

### 随堂练习

**题目**：build.rs 编了 .slint，为什么还要写 include_modules!？

提示：想想「生成代码」和「把生成的代码引入当前模块」是不是同一件事

**答案讲解**：两者分工不同。build.rs 只在编译期生成 Rust 源码，产物放在构建目录里；include_modules! 才是把产物引入当前模块的入口。少了它，MainWindow 这个类型根本不存在。

### 知识地图

1. **三件套与职责**（P08）—— Cargo.toml、build.rs、ui 的分工，后面所有集都跑在这套流程上
2. **组件名映射**（P16）—— export 的组件名就是宿主侧的类型名，是两边对接的锚点
3. **实时预览的边界**（P16）—— 改宿主接口就得重启，这条规律在集成阶段还会再撞上

**Memory Game ①** · 视频 9.72 分钟 · `ep03.mp4`

### 本集目标

1. **把一块牌做成组件** —— 会写 component + inherits，说得出为什么选 Rectangle

### 核心规则

- **定义不等于实例** —— component 不写实例化就不会出现在屏幕上
- **花括号不能省** —— MemoryTile {} 是空实例的标准写法
- **parent 指父元素** —— Image 的 parent 是底板，不是窗口
- **位置** —— icons 与 .slint 同级，路径才短
- **命名** —— at、bus、cloud…与代码里的字符串逐字一致
- **打包** —— 资源随二进制走，发布不带素材目录
- **重复出现** —— 第二块牌出现时，就该有组件了
- **需要外部传参** —— 图标、状态要由使用者决定

### 关键结论

- **4 × 74px − 10px = 286px**：两侧各 20px → 窗口 326px、每个数字只有一个出处
- **64px 是逻辑像素**：高分屏自动放大、单位是类型的一部分
- **64 与 64px 是两个类型**：混算直接编译失败、单位让缩放自动生效
- **宽高只写一遍**：其余全部 绑定 推导、改尺寸只动一处

- 64px 的 px 不是可有可无的后缀，是类型的一部分。
- 的文件 import 不到，宿主也看不见它。

## P04 · 幕布、点击与动画

**Memory Game ②** · 视频 9.56 分钟 · `ep04.mp4`

### 本集目标

1. **让元素响应输入** —— 会用 TouchArea 的 clicked、pressed 与 has-hover
2. **用声明顺序控制层级** —— 理解后声明的元素盖在上面，Slint 没有 z-index
3. **让变化带上动画** —— 会用 animate 包装 width、x、background 的变化

### 核心规则

- **绘制** —— 后声明的元素画在上面
- **命中** —— 点击先交给最上层的元素
- **陷阱** —— 铺满的 TouchArea 会挡住下面的点击
- **root** —— 组件最外层，跨层指回组件
- **self** —— 当前这个元素，写在哪指哪
- **parent** —— 直接父元素，隔层就断
- **in** —— 组件的输入，使用者负责设值
- **out** —— 组件的输出，内部决定、外部只读

### 关键结论

- **声明顺序 = 绘制顺序**：后面的在上层、没有 z-index 这回事
- **Slint 没有 z-index**：层级 = 声明位置、或者封成子组件
- **TouchArea 只负责收到**：长什么样、变不变色，自己绑、外观与交互拆开

### 容易踩的坑

- 人的那组元素封成子组件，让它整体后声明。
- 它会挡住下面的点击——布局时要想清楚谁在最上层接收事件。
- 的元素上，悬停变色、按下变深，不用写一行命令式代码。
- 声明处只写类型，处理器里自己起参数名，两边靠位置对应，改顺序要一起改。
- 翻转那行代码写在 MainWindow 里，不是 MemoryTile 内部——self 指的是这块牌，但代码站在使用者。

### 随堂练习

3. **用双向绑定打通层级** —— 会把子元素属性和回调暴露到顶层，供宿主使用

### 核心规则

- **求值即登记** —— 读到哪个属性，就依赖哪个
- **没走到的分支** —— 里面的属性暂时不算依赖

- 担心漏更新，条件本身也是依赖。
- 指望它每帧刷新——需要每帧变化的是动画，不是绑定。
- 人怎么用这个按钮，接口就长什么样。

3. **判断用函数还是回调** —— 按「谁来实现」这一条标准做选择

### 核心规则

- **先看自己** —— self 上的成员优先级最高
- **再往外找** —— 逐层向上，直到组件根
- **限定名** —— 写了元素名就只在该元素上找

- **表达式产生值，语句产生动作**：绑定只收表达式、处理器只写语句、分界即设计
- **绑定写关系，语句写步骤**：函数内部用，回调跨语言、边界感

- 顺手，比先转数字再除干净。
- 指望读者替你做推断。
- 边界：这些语句只在处理器被触发时执行一次，和绑定那种「持续成立的关系」完全不同。
- 扭，其实是在守住声明式的边界，别指望回调里写算法。

**答案讲解**：私有函数的纯度由编译器从函数体推断：只读属性、只做计算就算纯；一旦有赋值或调用不纯的东西，就不纯了。public 和 protected 必须显式声明 pure，因为跨组件调用时编译器不再替你推断。

## P12 · 回调与全局单例

**语言核心 ⑤** · 视频 10.32 分钟 · `ep12.mp4`

### 本集目标

1. **说清回调的三步与限制** —— 声明、处理、触发之外，还要知道没人接时会怎样
2. **会用全局组织共享状态** —— 明白全局能放什么、范围到哪、怎么让宿主看见
3. **掌握两个隐式钩子** —— changed 与 init 的触发时机和代价

### 核心规则

- **最多一个** —— 同一回调设两个处理器是编译错误
- **触发一次** —— 执行一次，不会叠加
- **处理器形态** —— 一行表达式，或一个代码块
- **返回值** —— 代码块最后一行即是
- **必须省略参数** —— 别名声明里写括号是编译错误
- **签名一致** —— 参数与返回值必须完全相同
- **纯度一致** —— 一边纯一边不纯是错误
- **双向触发** —— 处理器设任一侧都能收到

### 关键结论

- **回调往外，全局放下**：一个组件树一份全局、窗口之间不共享、事件与状态两条线
- **一个组件树一份**：窗口之间不共享、托盘图标另算一份、回调要重新注册
- **回调 = 事件出口**：全局 = 共享状态与业务桥、跨语言协议齐了

### 容易踩的坑

- ：没有处理器时返回的是类型的默认值，数字 0、布尔假、空串。
- 人的回调写成带名字的参数不用奇怪，那只是注释；跨语言时真正对齐的是类型，名字根本传不过去。
- 名用双向绑定的符号，但有三条硬规矩：声明别名时必须省略参数列表；两边签名必须完全一致；纯度也要一致，一边纯一边不纯是编译。
- 「单例」的含义：每个窗口实例有自己的一份，全局不跨窗口共享——文档特意标注了这一点。
- 把单例理解成进程级全局变量，那样迟早出问题。

### 随堂练习

**题目**：全局里写 100px / 1phx 会编译不过，同样的式子放在组件里却可以。为什么？

提示：全局有没有自己的窗口

**答案讲解**：全局不属于任何窗口，没有缩放系数，逻辑像素和物理像素之间没法换算，rem 转长度也一样。组件活在窗口里，缩放系数已知，所以算得出来。结论是全局只存语义值，跟屏幕相关的换算留在组件里。

### 知识地图

1. **回调是出口**（P16）—— 组件把事件交出去，宿主决定做什么
2. **全局是共享**（P15）—— 一个组件树一份，跨窗口各一份
3. **隐式钩子要慎用**（P13）—— changed 与 init 方便，但代价要认

### 核心规则

- **只写自己的** —— other.property 是编译错误
- **全局不行** —— global 里写 animate 直接报错
- **一个属性一个** —— 同属性挂两个 animate 是错误

- **duration** —— 走完全程用多久

- **delay** —— 什么时候开始

## P14 · 显式定位与布局元素

**布局系统** · 视频 9.56 分钟 · `ep14.mp4`

### 本集目标

1. **分清两条定位路线** —— 知道什么时候手写 x/y，什么时候必须交给布局元素
2. **看懂空间怎么分** —— 能用 min/max/preferred 和 stretch 解释布局结果
3. **会用容器组件** —— 知道 @children 把使用处的子元素插在哪一层

### 核心规则

- **不能写 x / y** —— 布局子元素的位置由布局决定，写了是编译错误
- **写了宽高就固定** —— 在布局里 width / height 是精确尺寸，不再伸缩
- **百分比也是精确值** —— width: 50% 等于父宽一半，不参与空间分配
- **相对父元素** —— width: 50% 等价于 parent.width * 50%
- **根组件例外** —— 根组件不继承 Window 时，百分比被忽略
- **布局里是精确值** —— 布局把它当固定尺寸，不再参与伸缩
- **填满父元素** —— Rectangle / TouchArea / FocusScope / Flickable
- **按内容** —— Text / Image / 多数控件

### 关键结论

- **一路相加，到窗口才是绝对位置**：x / y 相对父元素、absolute-position 只读、拖拽最易翻车
- **GridBox = GridLayout + StyleMetrics 默认值**：间距跟着主题走、要精确就用 GridLayout
- **声明约束，引擎求解**：min / max / preferred / stretch、布局四要素

### 容易踩的坑

- 翻车：拿父坐标系的值去比窗口尺寸，位置就会偏一截。
- 错的是混着来，行列基准就对不上。
- 要分清 if 和 visible：条件为假时 if 元素从布局里彻底移除，兄弟元素重新瓜分空间；visible: fal。

### 随堂练习

**题目**：布局的子元素上写 x: 10px 会报错，那写 width: 100px 为什么能通过？

提示：想想「合法」和「符合你的本意」是不是一回事

**答案讲解**：写 x 是编译错误，因为布局子元素的位置由布局决定，不允许手动指定。写 width 合法，但含义变了：元素在布局里成了固定宽度，不再参与伸缩。想要比例用 stretch，想要留白用 padding。

### 知识地图

1. **布局是约束**（P08）—— 位置尺寸来自绑定，与属性系统同源
2. **约束与伸缩**（P14）—— min / max / preferred 加 stretch 解释所有布局结果
3. **容器组件**（P15）—— @children 决定使用处子元素落在哪一层

### 核心规则

- **property** —— in 只读、out 只写、in-out 可读写，默认 private
- **callback** —— 声明事件，使用处用 =\> 接或转发
- **** —— 把内部属性与回调焊成组件接口

### 关键结论

- **Box = 布局 + 主题默认值**：间距随风格、max-height 可压回内容高
- **自定义控件 = 组合已有元素**：接口用 in/out/callback 声明、没有新语法

- Window、Rectangle 这些内置元素不需要导入，只有组件库和自定义组件需要。
- 差别只在内部写好了行为。
- 手法：动画不直接加在 x 上，而是加在中间属性上，因为 x 的表达式已经承担了几何计算，两层职责分开各管各的。

## P16 · 数据模型与跨平台发布

**收官** · 视频 9.98 分钟 · `ep16.mp4`

### 本集目标

1. **看懂 for 的原料** —— 知道整数、数组、宿主模型三种模型来源的区别
2. **摸清宿主接口** —— 认得 Model trait、get/set/on 与 Timer 这套动词
3. **知道怎么发出去** —— 桌面、Web、移动三条发布路线各需要什么

### 核心规则

- **length** —— 只读，元素个数
- **push / remove / insert** —— 尾部追加、按索引删、按索引插
- **越界不报错** —— 读越界返回默认值，写越界什么也不做
- **编译期打包** —— .slint、图片、字体都进可执行文件
- **C++ 要显式开** —— SLINT_EMBED_RESOURCES 设为 embed-files
- **路径别写死** —— 运行期按绝对路径读资源，换机器就崩
- **安全区** —— safe-area-insets 避开刘海与导航栏
- **虚拟键盘** —— virtual-keyboard-size 判断是否弹出

### 关键结论

- **数据不在内存里，才值得自己实现**：数据库分页、十万行以上、行数据要现算
- **课程完结**：docs.slint.dev · GitHub 示例 · 社区、下个项目见

### 容易踩的坑

- 界面只声明「每条数据长什么样」。
- 在宿主侧：前两种不可变，模型可变可通知。
- 漏的正是第三个——数据改了没发通知，界面纹丝不动，还不报错，你只能靠猜。
- 两点：clone 的是 Rc 不是数据；捕获窗口要用 as_weak，否则回调握着强句柄，组件永远释放不掉。
- 在里面做重活——它是取一行，不是加载一页。

### 随堂练习

**题目**：VecModel 里加了一行数据，界面却没变，最可能漏了什么？

提示：先确认数据真的进了模型，再确认模型有没有通知出去

**答案讲解**：最可能是没走模型的通知。VecModel 的 push、remove、set_row_data 会自动发通知；自己实现 Model 时容易漏：改了数据不调 row_changed，界面就停在旧值。

1. **for 与模型**（P16）—— 三种原料背后是同一个 Model 抽象
2. **跨平台发布**（P16）—— release 内嵌资源，Web / 移动 / 嵌入式各走工具链
3. **一条根**（P01）—— 声明式 UI、逻辑留宿主，十六集反复验证的同一件事
