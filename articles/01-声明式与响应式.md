# 声明式与响应式

> 从「创建按钮的三行代码」到「只重算依赖变化的部分」——Slint 课程配套图文之一（P01 / P09）

## 导语

命令式界面写步骤，声明式界面写结构，这个差别是后面所有语法的挂靠点。Slint 把「属性变了，界面自动更新」做成语言内建的细粒度响应式，而非外挂的订阅机制；理解这张依赖图，才能解释绑定为何失效。本文把 P01 01:26 的命令式创建按钮、P01 03:05 的纯声明式结构、P01 04:12 的「只有依赖变了才重算」，串到 P09 02:02 的「依赖变了，自动重算」与 P09 06:58 的「绑定只声明一次」，对应视频 P01、P09 两集。

## 一、命令式写步骤，声明式写结构

用 JavaScript 创建按钮要三步：createElement、设文字、appendChild。三步之间按钮处于「技术上存在、界面上看不见」的中间态，组件一多就无法从代码想象界面。XML 加 code-behind 把界面与逻辑拆成两张皮；React 的 JSX、SwiftUI 的 DSL 进了一大步，本质仍是「在通用语言里模拟声明式」：写函数调用，靠虚拟 DOM 的 diff 或视图重建在运行时反推结构。

Slint 是元素名加花括号、属性用冒号、嵌套即父子，没有标签与尖括号，读代码就是读界面结构。`examples/p01_s08.slint` 把官方示例包进 Window 以便单独预览：

```slint
    Rectangle {
        width: 150px;
        height: 60px;
        background: white;
        border-radius: 10px;

        Text {
            text: "Hello World!";
            font-size: 24px;
            color: black;
        }
    }
```

文件 `examples/p01_s08.slint` · 预览 `slint-viewer examples/p01_s08.slint`

一个矩形里嵌一段文字，不跑程序也能看出形状。描述对象从「怎么做」换成「界面长什么样」，这是后面一切差异的起点（P01 01:26、02:15、03:05）。

## 二、为什么不改造通用语言，而是另起一门

JSX 的吸引力是「什么都能写」：界面里能发请求、算数据、改全局状态。原型阶段快，半年后 UI 结构、网络逻辑与数据处理混在一个文件，没人敢动。Slint 刻意不提供这种自由——它没有改造现有语言，而是从零设计纯声明式语言，语言层面装不下业务逻辑，计算必须回到 Rust、C++、JavaScript 或 Python，两边只通过属性与回调通信。

官方文档称之为「真正的声明式语言」：边界由编译器而非团队纪律保证，换来界面可读、设计师可改、两侧工具链纯粹。Rust 侧启动只有 `include_modules!`、`App::new()`、`run()` 三行，编译期宏把 `.slint` 编成强类型结构体，声明的属性与回调都有类型安全的方法。同一份 `.slint` 在微控制器、嵌入式 Linux、桌面与移动、WebAssembly 上共用，在四种宿主语言里长得一样。代价也明确：Slint 只能表达 UI，这不是疏漏，是设计（P01 02:41、05:22、06:31、07:20）。

## 三、绑定是一张依赖图，只重算依赖变化的部分

给属性赋表达式，它就成为绑定。`examples/p09_s06.slint` 是最小的一条：

```slint
export component Example {
    in-out property<int> my-property;

    // 这是一条绑定：依赖 my-property
    width: root.my-property * 20px;
}
```

文件 `examples/p09_s06.slint` · 预览 `slint-viewer examples/p09_s06.slint`

`width` 依赖 `my-property`，后者变，前者自动拿新值，代码里没有「更新宽度」。机制不是全量重渲染：求值时实际读到的属性各登记一条依赖，属性变化只把依赖它的绑定标脏，值被读取时才惰性重算，没人读就不算。因此 `if` 分支没走到时里面的属性暂时不算依赖，而条件本身是依赖，会重新求值并重新登记。绑定是带缓存的惰性求值，不是每帧刷新的动画循环。

`examples/p01_s12.slint` 把三条绑定压进一个矩形：

```slint
    myRect := Rectangle {
        x: ta.mouse-x;
        y: ta.mouse-y;
        width: 60px;
        background: ta.pressed ? orange : skyblue;
        Text {
            text: "x: " + (myRect.x / 1px);
        }
    }
```

文件 `examples/p01_s12.slint` · 预览 `slint-viewer examples/p01_s12.slint`

位置跟随鼠标、按下换色、文本实时显示坐标，十几行声明产生三个动态效果，没有一行同步界面的代码。运行时维护依赖图，变化沿图传播，只重算真正受影响的绑定，这是官方所说细粒度响应式，也是不需要虚拟 DOM 的底气（P01 04:12、04:37；P09 02:02、02:23、02:41、07:40）。

## 四、绑定只声明一次：一次赋值就掐断它

绑定只在属性「持有它」期间有效：它是声明处写死的长期关系，一旦在回调里给属性赋新值如 `w = 100px`，旧绑定即被替换，此后依赖变化也不再跟随。反例在 `compile-fail/p01_s13.slint`（P01 04:59），标注诊断为 `warning: assignment will overwrite the binding`。`TextInput` 是同一坑的变体：用户打字本质是对 `text` 赋值，第一次输入就掐断绑定（P11 07:39）。

要既可由外部改、又保持同步，用双向绑定 `<=>` 让两个属性指向同一份存储，或改上游属性、用变化回调抄走值。`examples/p09_s18.slint` 演示前者：

```slint
export component MyButton inherits Rectangle {
    in-out property <string> text <=> txt.text;
    callback clicked <=> touch.clicked;

    txt := Text { text: "默认文字"; }
    touch := TouchArea { }
}
```

文件 `examples/p09_s18.slint` · 预览 `slint-viewer examples/p09_s18.slint`

同一符号还能把子元素属性上提到顶层、把内部回调转发出去，要求两侧类型一致且都可写。经验法则：随依赖自动变的用绑定，用户操作产生的瞬时修改才用语句赋值。更隐蔽的错是绑定绕成环，诊断会指明参与的属性，砍掉一边让依赖保持单向即可（P09 06:58、07:21）。

## 五、纯声明式带来的自由与限制

自由：组件靠组合复用，属性与回调是 UI 和逻辑唯一通道，界面文件没有对象生命周期与手动刷新，设计师也读得懂。限制同样由语言写死：回调处理器只有 `let`、`if`、`return`、赋值等少数语句，没有 `for`、`while`，重复交给元素树的 `for` 元素；绑定只收表达式且必须无副作用，想调用的函数得是纯的，私有函数纯度由编译器从函数体推断；代码块必须有返回值，`:=` 是给元素起名，不是赋值运算符。Slint 用「表达不了业务逻辑」换来了「界面永远只是界面」。

版本需如实说明：官方文档以 edition 1.20 为例，仓库制作时本机可用版本为 Slint 1.18.1，所有工程锁 `=1.18.1` 并用该版本实测。官方示例的 `#[edition = "1.20"]` 在 1.18.1 下解析失败，还原工程时已移除；「1.19 起 `if` 里的 Text 也参与父元素尺寸计算」这类行为变化，1.18.1 仍按旧规则，P04 / P14 的两处绑定环诊断及上面那条赋值警告在本机均未复现，不能声称仓库能直接跑出。改用 1.20 及以上版本时改回版本并加回 edition 属性即可。

## 常见坑

1. 改完属性还去找订阅或手动刷新接口；绑定声明一次就长期成立（P01 04:12、P09 02:41）。
2. 在回调里给已绑定属性赋值，或把 `text` 单向绑到 `TextInput` 又指望输入后仍同步；改用双向绑定或变化回调（P01 04:59、P09 06:58、P11 07:39）。
3. 把动画节奏或副作用塞进绑定表达式；绑定是惰性缓存，逐帧变化交给动画（P09 02:41、P11 05:26）。
4. 担心 `if` 分支里的属性变化不会触发更新；条件本身是依赖，真正没读到的分支才不算依赖（P09 02:23）。
5. 代码块忘了 `return` 得到「类型不匹配」；把 `:=` 当赋值运算符同样报错（P09 01:43、P11 03:41）。
6. 照搬 edition 1.20 示例，或期待 1.19 的布局变化在本机复现；仓库锁 1.18.1，相关诊断未复现。

## 小结

组件是结构，属性是数据，绑定是关系——P01 与 P09 铺完响应式 UI 的地基：声明式语言描述界面，细粒度依赖追踪只重算该重算的部分，业务逻辑留在宿主语言。完整逐集讲解见 B 站视频合集，示例与六个渐进工程都在配套代码仓库 `slint-course-kit`；把两集示例亲手敲一遍，再进入 P10 看属性类型。
