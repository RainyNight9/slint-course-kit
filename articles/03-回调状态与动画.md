# 回调、状态与动画

> 从「事件怎么送出组件」到「属性变化怎么变慢」——Slint 课程配套图文之三（P04 / P12 / P13）

## 导语

组件描述结构，属性承载数据，绑定让数据自动流动；界面要响应人、跨语言协作、带上时间感，还缺回调、全局单例、状态与动画。四者共用一条底层规则：没有事件循环对象，也没有动画播放器，一切都是属性值的变化与依赖。本文把 P04 02:52 的回调转发、P04 04:50 的幕布滑开、P12 01:19 的回调三步与 P13 01:18 的属性动画串成一条线，对应视频 P04、P12、P13 三集。

## 一、回调：组件对外的事件出口

回调三步：组件里 `callback` 声明，使用处 `=>` 挂处理器，代码里以名字加括号触发。`examples/p12_s04.slint` 收全了三步：

```slint
export component Example inherits Rectangle {
    callback hello;               // 声明
    area := TouchArea {
        clicked => {              // 处理
            root.hello();          // 触发
        }
    }
}
```

文件 `examples/p12_s04.slint` · 预览 `slint-viewer examples/p12_s04.slint`

`root.` 指组件最外层，隔多少层都能指回组件，内部元素转发事件必须带它；`self` 指当前元素，`parent` 只够到直接父级。声明可带参数与返回值，`callback hello(int, int) -> int;` 由处理器实现计算（P12 02:31）；参数名只是注释，跨语言对齐的是类型（P12 02:51）。一个回调最多一个处理器；没人接时触发静默，带返回值只拿到类型默认值 0、false、空串（P12 01:47、02:11）。别名转发写 `callback clicked <=> area.clicked`，须省略参数列表、签名一致、纯度一致（P12 03:13、03:34）。

宿主侧用组件的 `on_<回调名>` 注册实现，导出全局则 `app.global::<Logic>()` 配 `on_` 与 `set_`（P12 05:25、05:48）。记忆游戏即如此：`MainWindow` 声明 `callback check_if_pair_solved()`，瓷砖处理器调 `root.check_if_pair_solved()`，判定交给 Rust 的 `on_check_if_pair_solved`（P04 02:52）。

## 二、全局单例：共享状态与业务桥

全局单例以「名字点成员」访问，典型用途是调色板：

```slint
global Palette {
    in-out property<color> primary: blue;
    in-out property<color> secondary: green;
}

export component Example inherits Rectangle {
    background: Palette.primary;
    border-color: Palette.secondary;
}
```

文件 `examples/p12_s11.slint` · 预览 `slint-viewer examples/p12_s11.slint`

全局只装属性、回调、函数，元素、状态、动画与 `init` 都写不进去（P12 04:19）。单例范围到窗口为止：一个组件树共用一份，第二个窗口是新实例，属性回初值、回调要重新注册（P12 05:03）。全局不属于窗口，没有缩放系数，`100px / 1phx` 在全局编译不过、放进组件却可以，屏幕相关换算应留在组件（P12 04:42）。`export global Logic` 还须在导出主组件的文件里再导出一次，宿主才看得见（P12 05:25、05:48）。官方 to-upper-case 示例把绑定、`pure callback` 与 Rust 实现接成三层：绑定不许有副作用，能进绑定的回调必须标 `pure`（P12 06:10）；组件也可用双向绑定把全局成员挂到自身属性，隐藏全局（P12 06:33）。`changed` 排队到下一轮并合并同轮变化，`init` 实例化时从里往外各跑一次；能用绑定表达的关系别交给 `changed`（P12 07:18、07:40、08:00）。

## 三、animate：把属性变化包装成过渡

没有动画对象，也没有时间轴，唯一原料是属性值的变化。`animate` 声明「变化时慢慢过去」，无论变化来自绑定重算、状态切换还是宿主 `set_`，声明一次处处生效（P13 00:58、01:18）：

```slint
export component Example inherits Window {
    background: area.pressed ? blue : red;
    animate background {
        duration: 250ms;
    }
    area := TouchArea { }
}
```

文件 `examples/p13_s04.slint` · 预览 `slint-viewer examples/p13_s04.slint`

能动的只有数字与颜色一族：整数、浮点、长度、物理长度、颜色、画刷、角度；字符串、布尔、图片、结构体写上去即报错。`animate` 只能管自己可写的属性，点别人的属性、写进 `global`、同属性挂两块都是错误（P13 01:39、02:03）。`duration` 管全程多久，`easing` 管速度分布，`delay` 管何时开始，另有 `iteration-count`、`direction`、`enabled`；一条声明可同时管多个属性，如 `animate x, y { duration: 100ms; }`（P13 02:22、03:41）。`spring(0.5)` 换目标时保留速度，连续点击会顺势拐弯（P13 02:46）；两个动画接先后只靠给后者加 `delay`（P13 03:22）。纯随时间走的持续动画改用 `animation-tick()`（P13 03:05）；系统减少动效开关打开后，新动画直接跳到目标值（P13 07:26）。

## 四、states 与 in / out：成套的值与进出节奏

多个属性要一起变，用 `states` 声明「名字、条件、属性组」。条件按源码顺序求值，第一个命中生效，所以特殊的在上、兜底在下（P13 03:58、04:44）。状态激活期间接管列出的属性，无命中时回落到自己的绑定或默认尺寸（P13 04:23、05:05）。进出动画写在状态块内的 `in`、`out`、`in-out` 方向块，块里只放 `animate`；`animate *` 覆盖状态改到的所有属性，自动跳过布尔与字符串（P13 05:43、06:03）：

```slint
export component Example inherits Rectangle {
    in-out property <bool> pressed;
    states [
        down when pressed: {
            background: blue;
            in  { animate background { duration: 120ms; } }
            out { animate * { duration: 400ms; } }
        }
    ]
}
```

文件 `examples/p13_s18.slint` · 预览 `slint-viewer examples/p13_s18.slint`

独立的 `transitions [ ... ]` 写法已废弃，不要照抄。属性已有自己的 `animate` 又在过渡里被点名，编译不过；星号会跳过它（P13 06:22）。选择标准不是代码长短，而是有没有「一整组值」：单布尔驱动单属性用绑定加动画，成套切换才用 `states`（P13 06:41、07:07）。

## 五、幕布动画：四种机制合到一块瓷砖

`memory-game/step03-interaction/ui/app-window.slint` 是官方幕布动画的真实实现。`MemoryTile` 声明 `callback clicked` 与三个 `in` 属性，`TouchArea` 处理器只调 `root.clicked()`；`MainWindow` 里 `clicked => { self.open_curtain = !self.open_curtain; }` 才改值——`self` 指这块牌，代码却站在使用者一侧（P04 02:52、03:50、04:32）。幕布是声明在 `Image` 之后的两块深蓝矩形，按声明顺序天然盖住图标，Slint 没有 `z-index`（P04 00:56）。右幕布的 `x` 与 `width` 都绑三目，各配 250ms 的 `ease-in`：

```slint
    // Right curtain
    Rectangle {
        background: #193076;
        x: open_curtain ? parent.width : (parent.width / 2);
        width: open_curtain ? 0px : (parent.width / 2);
        height: parent.height;
        animate width { duration: 250ms; easing: ease-in; }
        animate x { duration: 250ms; easing: ease-in; }
    }
```

文件 `memory-game/step03-interaction/ui/app-window.slint` · 运行 `cargo run -p step03-interaction`

配色由 `background: solved ? #34CE57 : #3960D5;` 驱动，配 `animate background { duration: 800ms; }` 慢慢变绿（P04 05:53）。这里不需要 `states`：一个布尔驱动一个属性，绑定加动画就够；`icon` 提炼成 `in property <image>` 后十六块牌共用一个组件（P04 06:36）。读 `parent.width / 2` 安全是因为底板尺寸由外部给定，父元素若由内容撑开就会成环（P04 05:33）。

版本需如实说明：官方文档以 edition 1.20 为例，仓库制作时本机可用版本为 Slint 1.18.1，所有工程锁 `=1.18.1` 并实测；官方示例的 `#[edition = "1.20"]` 在 1.18.1 下解析失败，还原时已移除。P13 05:25 的「1.19 前 edition 无状态命中时宽高为 0px」是旧 edition 语义，依据是文件里的 edition 声明而非版本号。P04 05:33 的绑定环同属 1.19 起的行为变化，1.18.1 按旧规则不报该错误；`compile-fail/p04_s17.slint` 与 `compile-fail/p14_s11.slint` 是幻灯片节选，单独编译先报 parse error，实测见 `compile-fail/README.md`，不能声称仓库能复现课程诊断。

## 常见坑

1. 漏写 `root.`：内部处理器直接写 `clicked()`，或把翻面动作放进组件内部；对外回调须经 `root` 转发，改值放在 `MainWindow`（P04 02:52、04:32）。
2. 动画绑到错的属性：给 string、bool、image 写 `animate`，或点到别的元素、`global`，或同属性挂两块；只有自己可写的可插值属性能动（P13 01:39、02:03）。
3. 状态条件互斥不全：多条同时命中只取第一条，兜底须放最后，无命中时的回落值要心里有数（P13 04:44、05:05）。
4. 属性已有自己的 `animate` 又在 `in` / `out` 里被点名，编译不过；星号跳过它，想统一控制就别单独写 `animate`（P13 06:22）。
5. 以为回调必有人接：没人接时静默，带返回值只拿到 0、false、空串；也别设两个处理器（P12 01:47、02:11）。
6. 把 `global` 当进程级变量，或在全局里做 px/phx 换算、塞动画；照搬 edition 1.20 示例、期待 1.19 绑定环在 1.18.1 复现（P12 04:42、05:03；P13 02:03）。

## 小结

回调是出口，全局是共享，动画是属性变化的另一种读法。P04、P12、P13 把静态界面接上了人、宿主语言与时间：事件沿回调出门，状态沿全局与绑定流动，动效只调插值曲线。完整逐集讲解见 B 站视频合集，示例与六个渐进工程都在配套代码仓库 `slint-course-kit`；把幕布参数改一遍，再进入 P14 看布局系统。
