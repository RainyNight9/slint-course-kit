# 布局系统

> 从「手写 x/y」到「声明约束让引擎求解」——Slint 课程配套图文之四（P14）

## 导语

前面所有例子的坐标都是手算的，真实应用里窗口会缩放、内容会增减，这条路走不通。P14 把定位拆成两条路线：显式 x/y 与布局元素，并讲清 min / max / preferred 与 stretch 如何决定结果。规则多但都讲理。本文按「坐标系 → 布局分工 → 动态元素 → 绑定环 → 路线选择」递进，对应视频 P14 00:56、P14 02:02、P14 04:06、P14 03:47 与 P14 07:33。

## 一、两条路线与相对父元素的坐标系

Slint 给两条路：显式定位直接设 x、y、width、height，适合元素少且固定的静态场景；自动布局用布局元素表达几何关系，适合复杂、需随窗口缩放的界面。两者可以混用：布局管大框架，个别装饰元素手动定位（P14 00:56）。混用前记三条红线：布局子元素不能写 x / y，写了是编译错误；布局里写了宽高，元素就固定成那个尺寸不再伸缩；百分比在布局里不是分一半空间，而是一个精确尺寸（P14 01:21、02:47、07:58）。

x 和 y 从来不是绝对位置，而是相对父元素，真实坐标从根到叶一路相加；想拿窗口坐标用只读的 `absolute-position`，做拖拽、浮层时拿父坐标系的值去比窗口尺寸最容易偏一截（P14 01:43）。单位方面，px 是逻辑像素，随系统缩放系数换算物理像素，是推荐单位；phx 是物理像素，通常只用于一物理像素的细线或像素级对齐；百分比相对父元素，`width: 50%` 即 `parent.width * 50%`，根组件不继承 Window 时百分比被忽略（P14 02:02、02:26、02:47）。x、y 不写时默认居中于父元素；不写宽高时，Rectangle、TouchArea、FocusScope、Flickable 默认填满父元素，Text、Image 与多数控件按内容算，布局元素也默认填满父（P14 03:07、03:29）。

```slint
export component Example inherits Window {
    Rectangle {
        x: 100px;   // 相对父元素
        width: parent.width - self.x;  // 绑定算尺寸
    }
}
```

文件 `examples/p14_s06.slint` · 预览 `slint-viewer examples/p14_s06.slint`

`width: parent.width - self.x` 是绑定算尺寸，窗口一变它跟着重算（P14 02:02）。

## 二、三大布局的分工：spacing / padding / alignment

`VerticalLayout` 竖排、`HorizontalLayout` 横排、`GridLayout` 网格排，默认都拉伸子元素占满空间，嵌套即可搭出复杂界面（P14 04:06）。

```slint
export component Example inherits Window {
    HorizontalLayout {
        spacing: 5px;
        padding: 10px;
        Rectangle { background: blue; }
        Rectangle { background: yellow; }
    }
}
```

文件 `examples/p14_s12.slint` · 预览 `slint-viewer examples/p14_s12.slint`

三类布局共用 `spacing`（兄弟之间）与 `padding`（内容与边界之间），padding 还能拆成 `padding-left` / `right` / `top` / `bottom` 单独设；常见错是嵌套布局每层都写一遍 padding，留白翻倍还不自知，留白应集中在外层（P14 04:28；摘录见 `docs/snippets/p14.md`）。

`GridLayout` 两种写法：用 `Row` 一行行声明，或在元素上直接标 `row`、`col`，跨行跨列用 `rowspan`、`colspan`，这些属性运行时可改，配动画能做格子换位；两种写法别混着来，行列基准会对不上（P14 05:05、05:25）。

```slint
export component Example inherits Window {
    GridLayout {
        spacing: 5px;
        Rectangle { background: red; }
        Rectangle { background: blue; }
        Rectangle { background: yellow; row: 1; }
        Rectangle { background: green; }
        Rectangle { background: black; col: 2; row: 0; }
    }
}
```

文件 `examples/p14_s16.slint` · 预览 `slint-viewer examples/p14_s16.slint`

标准组件库还有 `GridBox`，本质是预填了 `StyleMetrics` 默认 padding 与 spacing 的 `GridLayout`：留白与旁边控件一致，代价是精确间距被风格盖掉，要精确控制就用 `GridLayout` 写数字（P14 05:45）。

空间分配有两个旋钮：`alignment` 决定沿主轴的整体对齐，默认 `stretch` 均分拉伸，另有 start、end、center、space-between、space-around；`stretch` 因子决定多出来的空间给谁，全是 1 就均分、设 2 拿两份、0 只守着 preferred 不参与拉伸，`min` / `max` 是伸缩越不过的硬边界，空间不够时按比例缩但不低于 min（P14 06:00、06:22）。两根轴最容易混：`alignment` 管主轴，交叉轴默认拉伸，要改用 `cross-axis-alignment`——竖排里想让按钮水平居中，改的是交叉轴而不是 `alignment`（P14 06:37）。

```slint
export component Example inherits Window {
    VerticalLayout {
        alignment: start;               // 主轴：上下
        cross-axis-alignment: center;   // 交叉轴：左右
        Text { text: "标题"; }
        Rectangle { width: 120px; height: 40px; }
    }
}
```

## 三、repeat、if 与容器组件的插入位

布局支持 `for` 与 `if`。`VerticalLayout`、`HorizontalLayout` 里可用 `for ... in 模型 : 元素` 按模型长出子项，网格里同样能用 `for` 和 `if`（P14 04:28、05:05；摘录见 `docs/snippets/p14.md`）。`if` 与 `visible` 必须分清：条件为假时 `if` 元素从布局里彻底移除，兄弟重新瓜分空间；`visible: false` 只是看不见，位置和间距照占。折叠面板、可隐藏侧栏这类交互要用 `if` 才符合预期（P14 06:55）。

使用处写在花括号里的子元素默认追加到根元素末尾；要指定位置，就在组件自己的元素树里放一个 `@children`，整个组件只能有一个，也不能放进 `for` 或 `if`（P14 07:15）。

```slint
component BoxWithLabel inherits GridLayout {
    Row { Text { text: "标题"; } }
    Row {
        @children    // 使用处写的子元素落在这里
    }
}
```

文件 `examples/p14_s22.slint` · 预览 `slint-viewer examples/p14_s22.slint`

布局的实质是：声明的不是坐标，而是首选多大、最小多大、最多多大、愿意为空间让步几分，窗口每次变化布局引擎重新求解（P14 07:33）。

## 四、子元素撑起父元素：绑定环的版本语义

父元素没写宽高时，preferred 尺寸从子往父推：取 x、y 未设置的那个最大 preferred 子元素（P14 03:47）。课程在 P14 03:47 讲的绑定环来自 1.19 起的行为变化：官方文档说明，1.19 前非布局父元素计算最小与首选尺寸时忽略 `if`、`for` 创建的子元素，1.19 起它们与直接声明的元素同样参与尺寸计算。于是 `compile-fail/p14_s11.slint` 那种写法——`if` 中的 `Text.text` 读 `parent.width`，父元素又跟着这段文本变宽——子读父、父跟着子，就成了环，编译器报 `The binding for the property 'text' is part of a binding loop`（P14 03:47）。解法是别让子元素读父尺寸：给父元素写死宽度，把 preferred 尺寸设为 `100%`，或让子元素的计算不依赖父宽（P14 03:47；官方文档 editions 1.19 节）。这是更新版本的语义，本机差异见文末说明。

## 五、何时显式、何时交给布局

判断标准不是代码长短，而是位置本身是不是数据。记忆游戏网格用显式定位：`memory-game/step04-grid/ui/app-window.slint` 里 `for tile[i] in memory_tiles` 生成的瓷砖用 `x: mod(i, 4) * 74px` 与 `y: floor(i / 4) * 74px` 定位，74px 等于 64px 瓷砖加 10px 间距，行列本身就是游戏数据，交给布局反而绕（P05 01:01；P14 00:56）。反过来，窗口要缩放、内容会增减、控件要成排对齐，就该交给布局：先判断横排还是竖排套一层布局，固定尺寸写死，剩下的交给伸缩，留白只在外层写一次。若发现自己在每层靠 x、y 微调，说明结构一开始就选错了，重搭比硬修快（P14 04:46、07:33）。

版本需如实说明：课程依据 Slint 官方文档（以 edition 1.20 为例），配套仓库制作时本机可用版本为 Slint 1.18.1，所有工程锁 `=1.18.1` 并用该版本实测。官方示例的 `#[edition = "1.20"]` 在 1.18.1 下解析失败，还原工程时已移除。P14 03:47 的绑定环是「1.19 起 `if` / `for` 里的 Text 也参与父元素尺寸计算」这一行为变化带来的更新版本语义，本机 1.18.1 仍按旧规则，不报该错误；`compile-fail/p14_s11.slint` 与 `compile-fail/p04_s17.slint` 都是幻灯片节选，单独交给编译器先报 parse error，真实输出见 `compile-fail/README.md`，不能声称仓库里能复现课程诊断。要复现需 Slint 1.20 环境并把片段放进完整组件。

## 常见坑

1. 布局子元素写 x / y（编译错误），或写 width / height 后还指望伸缩、拿 50% 当伸缩开关（P14 01:21、02:47、07:58）。
2. 拿父坐标系的值比窗口尺寸：x / y 相对父元素，`absolute-position` 只读（P14 01:43）。
3. 嵌套布局每层都写一遍 padding，留白翻倍；spacing 管兄弟、padding 管边界（P14 04:28）。
4. 混用 Row 与 row/col 导致行列基准对不上；把 `alignment` 用在交叉轴上，该用 `cross-axis-alignment`（P14 05:25、06:37）。
5. 用 `visible: false` 代替 `if` 做折叠面板，元素仍占着位置和间距（P14 06:55）。
6. 照搬 edition 1.20 示例，或期待 1.19 的绑定环诊断在仓库 1.18.1 上复现（P14 03:47；`compile-fail/README.md`）。

## 小结

显式定位写坐标，自动布局写约束；前者适合静态、位置本身是数据的场景，后者交给引擎在每次窗口变化时求解。P14 把 min / max / preferred、stretch 与 spacing / padding 收成一套可解释的规则。完整逐集讲解见 B 站视频合集，示例与六个渐进工程都在配套代码仓库 `slint-course-kit`；把 P14 的布局例子挨个改一遍参数，再进入 P15 看标准组件库。
