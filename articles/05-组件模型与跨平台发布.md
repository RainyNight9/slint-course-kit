# 组件模型与跨平台发布

> 从「标准组件库与自定义控件」到「数据模型、宿主闭环与发布路线」——Slint 课程配套图文之五（P15 / P16）

## 导语

收官两集落在两件事：日常开发用什么控件，写好的界面怎样交到不同平台。P15 从 `import ... from "std-widgets.slint"`（P15 00:51）讲到自定义控件接口（P15 04:39），P16 从三种模型来源（P16 00:58）讲到 `cargo build --release`（P16 05:07）。压轴仍回到记忆游戏：P06 03:29 的「改的是副本还是模型」决定游戏能否跑通，P07 00:57 的 wasm 仅 Rust 决定它能否进浏览器。本文对应 P15、P16 两集并回扣 P06、P07，用 `memory-game/step06-game-logic/` 收拢「Slint 界面 + Rust 规则」的闭环。

## 一、先查标准库，再谈造轮子

标准组件库从 `std-widgets.slint` 导入，写法与导入自己的 `.slint` 文件一致；`Window`、`Rectangle`、`Text` 内置，无需导入，跨文件复用的组件才要 `export`（P15 00:51、P15 01:12）。控件分三组：Button、CheckBox、Slider 等基础控件，LineEdit、ListView、ScrollView、TabWidget 等视图类，以及 HorizontalBox、VerticalBox、GridBox 这组「布局元素加 StyleMetrics 默认间距」的盒子（P15 01:47、P15 02:29）。

ListView 只为可见范围实例化行，条目再多性能也稳定，代价是只接一个 `for`，自由排版改用 ScrollView（P15 02:14）。外观由风格决定，不指定时全平台默认 fluent，另有 material、cupertino、cosmic、native、qt 及 `-light` / `-dark` 变体；风格编译期定，入口是 `SLINT_STYLE`、`slint-viewer --style` 或编辑器设置，不是运行时属性（P15 02:42、P15 03:07）。全局单例 Palette 与 StyleMetrics 颜色只读、由当前风格填好，自定义控件一律从 Palette 取色，写死 `#fff` 在深色主题下会失效（P15 03:24）。

```slint
import { Palette } from "std-widgets.slint";
export component Example inherits Window {
    Rectangle {
        background: Palette.background;
        border-color: Palette.border;
        Text { color: Palette.foreground; }
    }
}
```

## 二、自定义控件：接口设计而非新语法

标准控件保底，设计未必迁就。该不该自己写，标准是行为而非颜色：颜色不合先换风格或改 Palette，要长按、要新交互才值得造控件（P15 03:39）。自定义控件没有新机制，仍是基础元素加绑定与动画拼装，接口只有三样——`in` / `out` / `in-out`（不写即 private）、`callback`，以及把子元素属性或回调焊到顶层的 `<=>`；原则是少暴露，辅助属性默认 private（P15 04:01、P15 04:21）。官方按钮配方即为一例（P15 04:39、P15 05:01）：

```slint
component Button inherits Rectangle {
    in-out property text <=> txt.text;
    callback clicked <=> touch.clicked;
    border-radius: root.height / 2;
    border-width: 1px;
    border-color: root.background.darker(25%);
    background: touch.pressed ? #6b8282
        : touch.has-hover ? #6c616c : #456;
    height: txt.preferred-height * 1.33;
    min-width: txt.preferred-width + 20px;
```

文件 `examples/p15_s16.slint` · 预览 `slint-viewer examples/p15_s16.slint`

圆角取高度一半，背景按按压、悬停分三档，宽高由 Text 的 preferred 尺寸加余量算出，不写死尺寸便随内容自适应（P15 05:18）；动画加在辅助属性上，让几何计算与节奏分开（P15 05:32）。Slint 里减号与下划线等价，生成宿主代码时统一换成下划线，`button-pressed` 到 Rust 里即 `on_button_pressed`（P15 06:31）。

## 三、数据模型：三种原料与写回的那道坎

`for`-`in` 的原料可以是整数、内联数组或宿主语言提供的模型；界面只声明「每条数据长什么样」，区别在宿主侧：前两种不可变，模型可变且能通知（P16 00:58）。`for` 后可跟条目名与 `[下标]` 两个可选标识符，网格靠 `mod(i, 4)` 算列、`floor(i / 4)` 算行（P16 01:19）。数组属性本身就是模型，能直接 `length`、`push`、`remove`、`insert`，越界不报错：读越界拿到默认值，写越界静默无操作（P16 01:40）。

Rust 侧对应 `Model` trait，只回答三个问题：有多少行、第几行是什么、变了怎么通知。现成实现 `VecModel` 的 `push`、`remove`、`set_row_data` 自动发通知；自己实现最容易漏第三个，不调 `row_changed` 界面就停在旧值且不报错（P16 01:59、P16 02:22、P16 02:58）。只有数据不在内存里——数据库分页、十万行以上、一行要现算——才值得自己实现，`row_data` 会被频繁调用，别在里面做重活（P16 03:22）。

最容易写错的是写回方向：`for` 里的条目是模型条目的引用，`tile.image_visible = true` 就直接写回模型（P16 03:43）；Rust 里 `row_data` 或迭代器交出的 `t1` 却是 `TileData` 的拷贝，改 `t1.solved` 模型毫不知情，必须 `set_row_data(idx, t1)` 才算写回（P06 03:29、P06 03:49）。这是 P06 的重点、记忆游戏跑通的关键。粒度上 `set_row_data` 只让依赖这一行的绑定重算，其余十五块牌不动，整体替换则全部重建（P06 04:11）。

## 四、从界面到规则：step06-game-logic 的完整闭环

`memory-game/step06-game-logic/` 把分工压进两个文件。UI 归 Slint，逻辑归 Rust：`ui/app-window.slint` 声明 `callback check_if_pair_solved()` 上报事件、`in property <bool> disable_tiles` 锁盘，规则、判定与计时全留给 `src/main.rs`（P06 01:02、P06 02:03）。点击只做两件事——写回模型、发回调，保证 Rust 看到最新状态；`disable_tiles` 是整盘共用的纯交互状态，不进模型（P06 02:27）。

```slint
            clicked => {
                // old: tile.image_visible = !tile.image_visible;
                // new:
                if (!root.disable_tiles) {
                    tile.image_visible = true;
                    root.check_if_pair_solved();
                }
            }
```

文件 `memory-game/step06-game-logic/ui/app-window.slint` · 运行 `cargo run -p step06-game-logic`

Rust 侧 `slint::include_modules!()` 引入生成代码，`MainWindow::new()` 构造窗口，`get_memory_tiles().iter().collect()` 取瓷砖、复制成八对并洗牌，用 `Rc::new(slint::VecModel::from(tiles))` 包成共享模型交给 `set_memory_tiles`（P16 01:59、P16 02:41）。`on_check_if_pair_solved` 的闭包筛出翻开且未消掉的两张牌，靠 `t1 == t2` 判定，配对就标 `solved` 后逐个写回：

```rust
        if let (Some((t1_idx, mut t1)), Some((t2_idx, mut t2))) =
            (flipped_tiles.next(), flipped_tiles.next())
        {
            let is_pair_solved = t1 == t2;
            if is_pair_solved {
                t1.solved = true;
                tiles_model.set_row_data(t1_idx, t1);
                t2.solved = true;
                tiles_model.set_row_data(t2_idx, t2);
            }
```

文件 `memory-game/step06-game-logic/src/main.rs` · 运行 `cargo run -p step06-game-logic`

两次写回驱动背景动画变绿，UI 不知道「配对」是什么（P06 03:49、P06 04:11）。未配对则 `set_disable_tiles(true)` 锁盘，用 `slint::Timer::single_shot` 一秒后盖回并再次写回（P06 04:51、P06 05:15）。宿主日常就是三个动词：`on_` 接事件、`get_` / `set_` 读写属性、`set_row_data` 刷模型（P16 04:01）。两处纪律：`new` 与 `run` 返回 `Result`，回调跑在 UI 线程，不能 sleep 或做重活（P16 04:30、P16 04:48）；组件持有回调、回调又捕获组件会成环，注册用 `as_weak()`、闭包里 `upgrade()`（P06 06:19、P15 07:00）。

## 五、多语言宿主、wasm 与发布

Slint 提供 Rust、C++ 一等集成，JavaScript/Node.js 与 Python 为 beta，同一份 `.slint` 在四种宿主里通用，官方 `slint-video/assets/code/` 也给了同一套游戏逻辑的四份宿主写法。跨端能力却不对称：官方文档以 caution 明确，只有 Rust 能编到 WebAssembly，C++、JS、Python 仍停在原生目标（P07 00:57）。

Web 路线在 P07 走完一遍：crate 改为 `cdylib` 并加 `[lib]` 指向 `main.rs`，`wasm_bindgen(start)` 用 `cfg_attr` 只在 wasm32 生效，`getrandom` 要开 `wasm_js`（P07 01:53、P07 02:45、P07 03:39）。`wasm-pack build --release --target web` 产出 `pkg`，页面给一块 `id = "canvas"` 的画布，import 生成的 js 并调用 `init()`；ES 模块不能从 `file://` 加载，得用 `python3 -m http.server`（P07 04:55、P07 05:26）。

桌面走 `cargo build --release`，`.slint`、图片、字体编译期内嵌，产物只依赖系统库；C++ 默认按路径加载资源，须显式设 `SLINT_EMBED_RESOURCES` 为 `embed-files`，否则绝对路径读图换机白屏（P16 05:07、P16 05:29）。之后按平台打包：Windows MSIX、macOS app bundle 签名公证、Linux Flatpak，Web 用 wasm-pack，Android 用 cargo-ndk、iOS 接 Xcode，嵌入式配 no_std（P16 05:50、P16 06:08）。浏览器里 Slint 画在 canvas 上用 WebGL，不碰 DOM 与 CSS，代价是文字自排、读屏读不到、无法被检索，官方不建议做通用网页应用；移动端用 `safe-area-insets` 避开刘海，输入框放进 ScrollView 应对虚拟键盘（P16 06:31、P16 06:51）。

需如实说明：`docs/snippets/p15.md`、`p16.md`、`p07.md`、`p06.md` 里的 wasm 命令、`Cargo.toml` 片段与跨语言宿主写法都是幻灯片教学摘录，不是独立可编译的工程，不能直接运行；P16 也没有对应的 `examples/p16_s*.slint`，全集内容都在摘录里。wasm 与打包相关内容本机未做实际编译验证，只是按官方文档整理。版本上，课程依据 Slint 官方文档（以 edition 1.20 为例），仓库制作时本机可用版本为 Slint 1.18.1，六个渐进工程全部锁 `=1.18.1` 并用该版本实测；官方示例的 `#[edition = "1.20"]` 在 1.18.1 下解析失败，还原工程时已移除，「1.19 起 `if` / `for` 里的元素也参与父元素尺寸计算」这类变化本机仍按旧规则，`compile-fail/README.md` 的诊断未复现，不能声称仓库能直接跑 1.20 专属语法。

## 常见坑

1. 给内置元素写 import，或组件忘了 `export` 就想跨文件复用（P15 01:12）。
2. 以为风格能运行时切换，或自定义控件写死 `#fff` 而不从 Palette 取色（P15 03:07、P15 03:24）。
3. 拿 ScrollView 堆长列表，或在 ListView 里塞多个子元素（P15 02:14）。
4. 改完 Rust 里 `row_data` 的副本就以为界面会变，或自实现 Model 漏 `row_changed`；写回必须 `set_row_data`（P06 03:29、P16 02:22）。
5. 回调闭包捕获窗口强句柄成环，或在界面线程 `sleep`、在 `row_data` 里做重活；用 `as_weak` / `upgrade` 与 `Timer` 替代（P06 06:19、P16 03:22、P16 04:48）。
6. 照搬 edition 1.20 示例、把 snippets 里的 wasm / Cargo.toml 摘录当成可运行工程，或用绝对路径读资源换机白屏（P16 05:29；`compile-fail/README.md`）。

## 小结

组件靠组合复用，数据靠模型驱动，逻辑留在宿主——P15 与 P16 把这套分工从控件库推到发布路线，记忆游戏是它最小也最完整的证据：界面只认数据，规则只认回调，一次 `set_row_data` 就让十六块牌各自动起来。完整逐集讲解见 B 站视频合集，示例与六个渐进工程都在配套代码仓库 `slint-course-kit`；把 `step06-game-logic` 亲手改一遍，这套地图才算走完。
