# 属性类型与表达式

> 从 property 声明到类型合同与纯函数约束——Slint 课程配套图文之二（P09 / P10 / P11）

## 导语

组件、属性、绑定构成响应式 UI 的地基，而属性里能装什么、关系能怎么写，由类型系统与表达式规则决定：类型是编译期签下的合同，跨语言同名同形；表达式写关系，语句写动作，分界即设计。本文把 P09 03:56 的四种可见性、P10 01:24 的 px 与 %、P10 05:23 的字符串插值、P11 00:56 的「表达式产生值，语句产生动作」与 P11 04:25 的 function 串成一条线，对应视频 P09、P10、P11 三集。

## 一、property 声明与四种可见性

元素身上的属性有三种来路：内置自带的、组件用 property 声明的、继承来的。自定属性写作 `property<类型> 名字`，类型必填，可选默认值——Slint 是静态类型语言，形状在编译期检查。不写默认值不等于没有值：int 是 0、bool 是 false、string 是空串、length 是 0px，长度 0px 的元素看不见。

限定符回答「谁能读、谁能写」，它是组件的接口契约：

```slint
export component Button {
    in property <string> text;      // 外部设
    out property <bool> pressed;    // 外部读
    in-out property <bool> checked; // 双向
    private property <bool> has-mouse; // 内部
}
```

文件 `examples/p09_s12.slint` · 预览 `slint-viewer examples/p09_s12.slint`

`in` 只允许外部写、组件内部读，适合按钮文字这类配置；`out` 反过来，适合 pressed 状态；`in-out` 两头都能写；`private` 完全内部，不写限定符即默认 private。组件导出后，只有顶层且非 private 的属性暴露给业务代码，短横线名字在 Rust 侧换成下划线并加 get_ / set_ 前缀；继承来的属性与子元素的属性不会自动冒到顶层，标准做法是在顶层声明一个属性，用 `<=>` 双向绑定连过去（P09 03:56、04:56、05:19、05:40）。

## 二、简单表达式、代码块与语句的边界

属性值最简单的写法是「属性名、冒号、表达式、分号」，复杂了换成代码块：块里写多条语句，最后 `return` 出值，末值即返回值。两种写法等价，但代码块必须有返回值，忘了 `return` 就是「类型不匹配」。`examples/p09_s05.slint` 把三种形态放在一起：

```slint
export component Example inherits Rectangle {
    width: 42px;              // 表达式 + 分号
    height: { 42px }          // 代码块，末值是返回值

    touch := TouchArea { }
    background: {
        if (touch.pressed) { return red; }
        return blue;
    }
}
```

文件 `examples/p09_s05.slint` · 预览 `slint-viewer examples/p09_s05.slint`

表达式产生值，语句产生动作：绑定只收表达式，处理器里只写语句。代码块能写的很少——表达式语句、赋值、let、if、return 与空语句，没有 for 也没有 while，重复交给元素树里的 for 元素；局部变量声明后不可变，赋值号左边只能是属性、字段、数组元素或 for 的当前项。`:=` 是给元素起名，不是赋值。比较与逻辑不可结合，`a == b == c` 直接报错，须加括号。名字从 self 起逐层向外解析到组件根（P09 01:03；P11 00:56、02:00、02:19、03:00、03:41、04:04）。

## 三、常用类型：单位是保护，命名是契约

length 必须带单位，几把尺子不能混：px 是逻辑像素，按屏幕缩放系数放大；phx 是物理像素，只用于像素级对齐；% 相对父元素；rem 相对默认字号。长度与纯数字不能直接相加，编译器直接拦下。换算就除以 1px 得到数字、乘 1px 变回长度，字面量 0 是唯一例外，可塞进任何带单位的类型：

```slint
export component Example {
    in-out property <length> w: 3 * 1px;
    in-out property <float> num: self.w / 1px;
    in-out property <length> back: num * 1px;
    in-out property <length> zero: 0;  // 字面量 0 通吃
}
```

文件 `examples/p10_s06.slint` · 预览 `slint-viewer examples/p10_s06.slint`

其余内置类型不多：int、float、bool、string、color（`#rrggbb` 或名字）、image（配合 `@image-url`）。数字转文本默认按当前区域的小数点符号，德语环境 1.5 写成 "1,5"，要固定格式用 to-fixed 或 to-string-unlocalized。struct 把字段打包成命名类型，export 后 Rust 侧生成同名结构体：

```slint
export struct Player {
    name: string,
    score: int,
}

export component Example {
    in-out property<Player> player: {
        name: "Foo", score: 100
    };
}
```

文件 `examples/p10_s10.slint` · 预览 `slint-viewer examples/p10_s10.slint`

字段默认值必须是编译期常量，写 42 可以、写 42.1 报错，因为小数点写法随区域变化；匿名与具名 struct 是两种类型，字段一样也不能互相赋值。enum 默认取第一个值，声明顺序有意义，引用带类型名前缀如 `CardSuit.spade`，类型已知处可省前缀但比较时只能省右边，值名不能与枚举同名。类型外加方括号是数组 `[T]`，对宿主暴露成模型，for 循环消费它；下标越界不报错，读返回默认值、写不生效（P10 01:24、02:08、02:51、03:34、03:57、04:19、04:40、06:25、06:48）。

## 四、字符串插值、函数与纯函数约束

拼显示文本不必手写加号串联：字符串里用 `\{表达式}` 直接嵌入，花括号里能放任意表达式乃至函数调用。反斜杠是转义开关，只认引号、反斜杠、换行、unicode 码点与插值花括号，跟别的字符就是错误；把界面写进 slint! 宏时插值会失效，因为宏先做一次转义，应在 Rust 侧格式化好再设进属性。

函数用 function 声明，参数与返回值都标类型，体里 return，默认私有；根级 public 函数其他组件乃至宿主语言都能调，protected 只给直接子类。pure 标记无副作用：不改属性、不触发回调、只做计算，只有 pure 函数能进绑定，因为绑定求值不许产生副作用，否则依赖追踪会乱。私有函数的纯度由编译器从函数体推断，public 与 protected 必须显式写 pure：

```slint
export component Example {
    property <string> my-property: my-function();

    pure function my-function() -> string {
        return "result";
    }
}
```

文件 `examples/p11_s13.slint` · 预览 `slint-viewer examples/p11_s13.slint`

mod、floor、round、max、min 等内置函数可前缀用也可点着用，接受带单位类型并返回同类型；函数与回调按「谁来实现」选，业务代码要响应就用回调，否则用函数（P10 05:23、05:46、06:08；P11 04:25、05:26、05:48、06:07、07:17）。

## 五、类型转换的窄门与常见编译诊断

隐式转换只开几道窄门：int 与 float 互转，float 转 int 截断；数字自动变字符串；带单位的类型不能直接变数字，得除以自身单位；字面量 0 通吃；struct 按共同字段转换，缺字段取默认值、多字段丢弃并警告。

```slint
export component Example {
    in-out property <int> cut: 45.8;       // 45
    in-out property <float> up: 42;        // 42.0
    in-out property <string> s: "n=" + 42; // 文本拼接
    // in-out property <int> bad: 12px;    // 报错
}
```

文件 `examples/p10_s21.slint` · 预览 `slint-viewer examples/p10_s21.slint`

「类型不匹配」多半是单位与数字混算、代码块忘 return 或比较连写。赋值掐断绑定对应 `warning: assignment will overwrite the binding`，绑定成环对应 `The binding for the property 'text' is part of a binding loop`。

## 常见坑

1. 代码块忘 return 得到「类型不匹配」；把 `:=` 当成赋值运算符（P09 01:43、P11 03:41）。
2. 把长度与纯数字混算，或直接把 12px 赋给 int；换算要除以 1px（P10 01:24、07:38）。
3. struct 字段默认值写 42.1 报错、写 42 可行，差别在区域小数点；匿名与具名不可混用（P10 03:57、04:19）。
4. 在绑定里调用没标 pure 的 public 函数，或以为私有函数也必须写 pure（P11 05:26、05:48）。
5. 字符串里写了不认识的反斜杠转义，或把 `\{...}` 插值写进 slint! 宏（P10 05:46、06:08）。
6. 照搬 edition 1.20 示例，期待 1.19 的绑定环诊断在本机复现；仓库锁 1.18.1，未复现。

## 小结

属性有类型，类型自成体系；表达式写关系，语句写动作。P09 到 P11 讲全了组件里流动的数据：限定符划接口，单位与命名类型签合同，纯函数守住绑定无副作用。完整逐集讲解见 B 站视频合集，示例与六个渐进工程都在配套代码仓库 `slint-course-kit`；把三段示例敲一遍，再进入 P12 看回调如何跨语言。
